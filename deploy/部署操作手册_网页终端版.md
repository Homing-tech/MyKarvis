# 部署操作手册（网页终端版，无需 SSH）

> 全程约 10 分钟：下载 1 个文件 → 网页终端上传 → 粘贴 1 条命令 → 照着输出清单在企微后台点 3 下。
> 部署包：`karvis-deploy.tar.gz`（60KB，已含全部代码 + `.env` 凭证 + DeepSeek Key）
> ⚠️ 部署包里带真实凭证，部署完从下载目录删掉即可。

---

## 第 1 步：下载部署包

从 WorkBuddy 会话里下载 `karvis-deploy.tar.gz` 到本机（比如下载目录）。

## 第 2 步：打开网页终端

腾讯云控制台 → 轻量应用服务器 → 找到 `49.235.107.213` 这台 → 点「登录」：

| 选项 | 说明 |
|---|---|
| **免密登录**（推荐） | 点进去直接就是终端（OrcaTerm） |
| 密码/密钥登录 | 输入你设置的 ubuntu 用户密码 |
| VNC 登录 | 备用，前两个不行再用 |

## 第 3 步：上传部署包

网页终端的工具栏 → **上传文件**按钮 → 选刚下载的 `karvis-deploy.tar.gz`。
上传后默认落在当前目录（一般是 `/home/ubuntu`），不用管具体位置，下一步的命令会自动找。

## 第 4 步：粘贴这一条命令，回车

```bash
T=$(find ~ /tmp /home -maxdepth 3 -name 'karvis-deploy.tar.gz' 2>/dev/null | head -1) && echo "找到部署包: $T" && mkdir -p /tmp/karvis_new && tar -xzf "$T" -C /tmp/karvis_new && sudo bash /tmp/karvis_new/deploy/server_setup.sh
```

这条命令会自动完成**全部六步**，屏幕上每步都有中文进度：

1. 前置检查（磁盘 ≥3G 才继续）
2. 备份旧 Karvis 项目和数据到 `/root/karvis_backup/`
3. 停掉旧 Karvis（自动识别是 Docker / systemd / 裸进程，三种都能停）
4. 验证 9000 端口已释放（不释放就停下来不硬上）
5. 新网关安装到 `/opt/karvis` + Docker 构建启动（国内拉镜像失败会自动换镜像源）
6. 自检：`/health` + 三个助手逻辑测试

## 第 5 步：照脚本最后输出的清单，做 3 件手工事

1. **腾讯云控制台 → 防火墙 → 添加规则**：放行 TCP `9000`，来源 `0.0.0.0/0`
2. **企业微信后台 → 我的企业 → 企业信息 → 企业可信 IP**：填 `49.235.107.213`
3. **企微后台 → 每个应用 → 接收消息 → 设置 API 接收**：

| 应用 | URL | Token / EncodingAESKey |
|---|---|---|
| 阿龙管家 | `http://49.235.107.213:9000/wecom/life` | 与 `.env` 的 `WECOM_LIFE_TOKEN/AESKEY` 一致（即你建应用时自己填的那组） |
| 埼玉教练 | `http://49.235.107.213:9000/wecom/fitness` | 建好应用后补 |
| 阿尼亚督导 | `http://49.235.107.213:9000/wecom/mood` | 建好应用后补 |

## 第 6 步：验证

在企微「阿龙管家」里发一句话（比如「记一下明天要交周报」），5–15 秒内应有回复。

- 没回复，在网页终端看日志：
  ```bash
  cd /opt/karvis && docker compose logs -f karvis
  ```
- 或者在服务器上模拟一条回调（不需要企微）：
  ```bash
  docker exec karvis python tools/mock_callback.py life "你好"
  ```
  注意：模拟回调会真实走企微推送，**必须先做完第 5 步第 2 项（可信 IP）**，否则会看到 `60020` —— 那说明凭证有效、只是 IP 没放行。

## 出错了怎么办

把网页终端里报错那一段复制发给我。常见三种：

| 报错 | 含义 | 处理 |
|---|---|---|
| `端口 9000 仍被占用` | 旧服务没停干净，脚本主动停下来保护现场 | 把 `ss -lntp \| grep 9000` 的输出发我 |
| `deploy 健康检查失败` | 容器起了但内部报错 | 把 `docker compose logs --tail 50` 发我 |
| `permission denied / sudo not found` | 当前用户没 sudo 权限 | 换「VNC 登录」用 root 试，或发我截图 |

## 想反悔（回滚旧版）

```bash
ls /root/karvis_backup/        # 旧项目备份都在这
cd /opt/karvis && docker compose down   # 停新网关
# 然后把备份解压回去，按原来的方式启动旧版即可
```
