# 埼玉教练 · 算法与规则出处

> v0.2.0 引入的三件能力（训练档案 / PR 追踪 / 渐进超负荷）中，**计算部分在代码里，判断部分在人格文件里**。
> 本文说明每个数字是怎么来的、规则抄自哪里，便于以后调参时知道动哪个文件。

## 一、1RM 估算：Epley 公式

**出处**：[GymCoach](https://github.com/Julien-Au/gymcoach)（Next.js 自托管健身应用，其负荷决策模块采用 Epley）。

**公式**：

```
估算 1RM = 重量 × (1 + 次数 / 30)
```

**代码位置**：`gateway/agents/fitness.py` → `epley_1rm()`

**示例**：60kg × 5 次 → `60 × (1 + 5/30)` = **70.0kg**

**为什么限制 ≤ 12 次**：Epley 是单次最大力量的经验公式，次数越高误差越大（>12 次时误差可达 ±15%）。
因此 >12 次只记为耐力记录，**不产出 1RM**，也不参与破 PR 判定。

**精度声明**：估算值误差约 ±5%，只能看趋势。所有播报文案都带「估」字，回复里不允许把估算值当实测成绩说。

## 二、破 PR 判定

**代码位置**：`_update_prs()`

| 规则 | 取值 | 理由 |
|---|---|---|
| 破 PR 阈值 | 新估 1RM − 历史最高 ≥ **0.5kg** | 留抖动余量，避免 0.1kg 的波动也播报 |
| 历史最高取法 | 同 `exercise_key` 的 `MAX(est_1rm)` | 只看峰值，不看最近一次 |
| 首条记录 | 记为「第一条 PR 基线」，不算破 PR | 没有对比对象 |
| 动作匹配 | 完全相等优先；无则取**最长包含匹配** | 避免「卧推」与「杠铃卧推」被拆成两条曲线 |

## 三、渐进超负荷决策表

**出处**：GymCoach 的 double progression（双进阶）思路 + 常规力量训练实践；
表达形式参考 [IronClaude](https://github.com/mosnicholas/iron-claude) 把规则写进提示词而非代码的做法。

**规则位置**：`assistants/fitness/AGENTS.md` → 「下次上多重（决策表）」——**改这张表不用发版**。

| 上次 RIR | 下次怎么调 |
|---|---|
| ≤ 2 | 上肢 +2.5kg / 下肢 +5kg |
| 3–4 | 重量不变，先加 1–2 次 |
| ≥ 5 或未填 | 重量不变，先把目标次数做满 |
| 连续 2 次无进展 | deload ×0.9 一周，或换动作 |
| 提到疼痛 | 不谈加重量，先减载；关节／尖锐／持续建议就医 |

**为什么用 RIR 而不是 RPE**：RIR（还剩几次力竭）比 RPE（主观强度 1–10）更容易口语表达——
「还剩 1 个」比「感觉 9 分」的个体差异小。两者可互转：`RIR ≈ 10 − RPE`（代码已支持 RPE 输入）。

**代码提供什么**：`_progression_hint()` 输出同动作最近 3 次记录 + 趋势文字（重量↑/↓/持平、次数变化、RIR 变化），
塞进上下文；**由人格文件里的决策表推导出具体重量**，代码不做判断。

## 四、训练档案

**出处**：IronClaude 的 onboarding 会产出「运动员档案」（目标 / 经验 / 器械 / 伤病 / 可用时间）。

**改造点**：IronClaude 是**五阶段连环追问**，本项目的用户画像是「口语、碎片、一句话交代完」，
连环追问会被无视 → 改为**顺带一问**：每次回复末尾追加一句提问，一次只问一组，答了就写进档案。

**存放位置**：`data/fitness/profile.md`（**不是** `assistants/`）

理由：`assistants/` 属代码层，`deploy/update.sh` 里有 `git reset --hard`，放那会被冲掉；
`data/` 是 Docker volume + 备份范围，且含伤病史属私密数据，与「健身数据属私密层」的约定一致。

**字段顺序（提问优先级）**：训练地点 → 可用器械 → 每周频率 → 主目标 → 训练年限 → 次要目标 → 伤病史 → 禁忌动作 → 体重 → 主要动作当前水平。
先问影响排动作的条件，再问目标，最后问基线。

**防骚扰机制**：`data/fitness/onboarding.json` 记录每个字段被问过几次，优先问「问得最少」的缺失字段，避免同一问题反复出现。

**写入规则**：只填**空字段**，不覆盖已填内容（防止误抽取污染）。用户想改请直接编辑 `profile.md` 或让教练重问。

## 五、简写解析

**出处**：GymCoach 的 `100x8@9` 简写语法 —— 用确定性解析绕过 LLM，快且不会抽错数字。

**代码位置**：`parse_shorthand()` / `extract_rir()`

| 输入 | 结果 |
|---|---|
| `卧推 60x5x5` | 60kg × 5 次 × 5 组 |
| `卧推 60kg×5 RIR2` | 60kg × 5 次 × 1 组，RIR 2 |
| `卧推 62.5x5x5 还剩1个` | RIR 1 |
| `卧推 60x5x5 RPE9` | RIR 1（RPE → RIR 转换） |
| `卧推 120斤x5x5` | 60kg |
| `卧推 5x5` | **不解析**（无单位的两个数字会被误读成 5kg，交给 LLM） |

判定要点：**三个数字**可以不带单位（可信）；**两个数字**必须带单位才认。

## 六、数据表

```sql
pr_record(
  exercise_key, exercise_name, weight_kg, reps, sets,
  est_1rm, rir, log_date, source_log_id, created_at
)
```

- `est_1rm` 为 NULL 表示 >12 次的耐力记录
- `source_log_id` 指回 `workout_log.id`，便于追溯原始输入
- 建表用 `CREATE TABLE IF NOT EXISTS`，老库自动生效，**不改动任何已有表**
